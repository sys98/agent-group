# Codex 交付编排

以本机 `/Users/yimijiu/.agents/skills/orca-dispatch/SKILL.md` 为流程参考，适配 **Codex 当前实际提供的工具**。保留先调查、计划先行、按波次派发、监督、固定基线双轴审查、集成验证与恢复；不伪造 Orca Run/Dispatch 或后台守护服务。参考与适配边界见 [references/orca-dispatch-mapping.md](references/orca-dispatch-mapping.md)。目标是用户可验证的产品结果，不是代理全部返回。

## 进入与权限

- 用户要求使用本技能进行编排，即选择代理协作；已有授权不逐票重问。委派、并行及模型选择仍受宿主和项目规则约束。
- 读取项目规则、上下文、当前改动和相关旧实现。用户纠正优先于旧规格；先把范围、非目标、业务验收与具体约束写入项目等价规格。
- 接管已有代理时先通知原负责人及其写入者停在安全检查点。消息接受不等于停写确认；未证明停止前只做调查和不重叠的准备，不启动第二个同文件写入者。
- 不因编排扩大提交、推送、部署、生产迁移、凭据或付费调用权限。不复制凭据或敏感运行配置进检查点。

## 调查与派发前计划

- 每次开始编排，先读 [references/matt-skill-routing.md](references/matt-skill-routing.md)，按其中触发条件**实际读取**对应 Matt 技能，不以本技能摘要替代。只加载当前阶段需要的技能；派发时把实施阶段的加载要求传给 worker。缺失时先按该表查找，无法恢复则明确受影响的门槛，不能宣称已执行。
- 先核对 Git 状态、分支、HEAD 和远程。配置了远程且允许访问时 fetch/readback；本地领先用本地基线并说明，分叉时先确定基线。不自动 pull、切分支或覆盖 dirty 内容。无远程按本地事实工作。
- 修 bug：coordinator 加载 `diagnosing-bugs`，完成阶段 1–4（实际最小失败命令、复现和缩小、3–5 个可证伪假设、逐个验证根因）；阶段 5–6 交实施代理。无法建立反馈循环时列出尝试与缺失证据，仅暂停该缺陷修复，不用猜测补丁替代诊断。
- 新功能先读现有 PRD、原型和真实调用链；有 PRD 不另跑 `to-spec`。加载 `grilling`，只问影响实现的未决决策，不重复询问已确定事项。大体明确最多两轮，尚未成熟或“先聊清楚”则持续到关键决策明确；用户说“够了”立即停止提问，记下未定默认。界面或状态逻辑靠文字无法确定时加载 `prototype`，按 UI/LOGIC 分支做一次性原型并记录结论与保存位置。不将 throwaway 原型整体当作生产实现；已验证决定及符合正式规范的纯逻辑可纳入正式实现，原型完整来源另行保留。
- **派发前先向用户汇报**：根因/已定决策、证据、默认假设、方案与风险、公开接口上的测试切入点；任务表列出目标、所有权、验收、波次、基线和模型选择依据。使用项目既有规格和计划位置，不另造第二套 PRD；项目明确要求的规格更新仍须完成。
- “先确认”或需求尚未成熟时等待明确答复，不能把沉默当作批准；其余已授权任务在汇报后继续。简单局部改动可直接完成，不强制派发。
- 读取 `to-tickets` 的切片规则来整理计划任务表，采用完整窄切片、真实阻塞边、必要预重构先行、全仓机械变更 expand–contract；按 `orca-dispatch` 覆盖其发布流程：不新建 tracker Issue、不配置标签、不额外启动一轮拆票确认。测试切入点按 Matt 联动规则随计划一并说明并传递既有确认。

## 最小任务账本

在项目现有计划机制中维护唯一账本；有 update_plan 时同步原生进度，否则用一份简短 Markdown，不重造 tracker/数据库。

每项写清：任务 ID、目标与非目标、依赖与波次、当前负责人/代理 ID、允许修改的文件或模块、工作目录/分支、输入基线、模型选择及依据、可观察验收、状态、证据位置与阻碍。任务状态可用：待调查 → 可实施 → 实施中 → 待审查 → 修复中 → 已验证/受阻。主代理独占账本、共享合同、迁移顺序和运行服务控制。

一个 Task 对应一个当前权威尝试；接续必须复用已有代理或显式移交。执行回执、心跳、代理最终消息和业务验证是不同证据，不能混淆。

## 调度与执行

- 工具存在时用 collaboration.spawn_agent / send_message / followup_task / list_agents / wait_agent；按本轮真实工具定义调用。不调用不存在的 worker_done、task-create 或虚构 CLI。
- 一次发出全部独立调查或实施任务，再处理主代理的独立工作。保留一个审查/故障处理槽，服从宿主并发上限；无需为了凑并发切碎同一语义目标。
- 经用户明确同意的共享工作区用互斥文件归属；共享文件指定唯一实施者串行修改，主代理协调合同。公开接口变更先通知消费者，更新后重新验证相关消费者；迁移编号与 predecessor 由主代理分配，不让并行代理自行猜 head。代理收到新需求先报告边界，不修改别人所有的文件。测试数据库、临时目录和产物路径按任务隔离。执行重建/清表测试前，白名单检查实际目标库名，并通过只读 current_database() 核对；仅环境变量非空不算隔离证明。
- 有用户未提交改动时默认保留原位，记录 HEAD 和受影响非敏感源码的哈希/差异范围；不为“固定基线”擅自提交、清理、reset 或建破坏性快照。确需 worktree 时按项目工具规则且保证实际包含所需工作基线。
- 主代理为 coordinator，负责调查、拆分、监督、验收和集成，不接手非琐碎业务实现。实施和修复交给实施代理；共享合同、迁移顺序由主代理决策后交指定唯一写入者落实。小改动直接执行的例外不扩展到大型任务。
- 每项是可独立验证的窄端到端切片，不机械分成前端/后端。冲突文件或真实依赖分到后续波次，当前波通过集成验证才启动下一波，并记录新基线。
- 有可用 worktree 工具且基线完整时，为实施代理使用独立分支/worktree，并核对真实 HEAD、base 和 common dir。dirty 输入不能靠新 worktree 自动继承；缺少正确隔离条件时只继续调查与规划，先解决基线，不默认为共享目录并行写入。用户已明确同意共享目录时才用互斥文件归属方式，记录这是隔离降级。
- 默认继承宿主模型，按仍待解决的问题和实际支持能力选择，不复制 Orca 的模型 ID 或声称不可观测的 effective 模型。用户指定优先；两次因能力不足验收失败时收窄任务或使用确实可用且获授权的更强配置，不以重复派发绕过问题。
- 候选实现者不能自称独立审查通过。
- 实施前给每个代理完整任务合同，模板见 [references/task-contract.md](references/task-contract.md)。约定检查点：开新文件前、测试后、交付前检查消息。

## 接收、审查、集成

收到代理结果后：核对任务/尝试、真实基线和改动归属 → 读实际 diff → 主代理亲自重跑适用检查 → **实际加载 Matt 的 `code-review`**，传入本波固定点、本次计划/任务合同和规范来源。Standards（编码后架构）与 Spec（本次计划、最新用户纠正）由两个独立只读代理并行检查；为审查预留并发槽，槽不足时分批，不能省去任一轴。审查固定到实际候选提交或 dirty 内容指纹，不能把未提交内容当成 HEAD 已覆盖。按技能传递完整 smell baseline，双轴报告分别保留、不合并重排；缺 spec 明确标记 Spec 未完成，不能算双轴通过。主代理另查边界、安全、回归与越权改动。相关修复交实施代理，重跑失效检查及审查。

- “已验证”要求测试/运行证明用户结果，并列出未验证和阻碍。测试通过不能证明上传、生产模型、跨节点恢复或视觉验收，分别取证。
- 当前已运行的测试库、生产库、服务端口和 Worker 不能被其他代理覆盖。仅主代理控制共享测试/服务重启，独立测试可并行。
- 当前波全部验收后，按项目约定串行集成分支，再跑集成基线上的 canonical 检查。提交/合并未获授权时保留候选，明确“未合并”；不能拿同目录可运行冒充 Git 集成。发生冲突或验证失败时保留现场，不自动回退已通过的结果，不启动依赖该波的下一波。
- 验收后先确认 writer 已停止，再清理本次拥有且已集成的代理、分支和 worktree；按当前工具支持执行，Git 分支只安全删除，dirty/未知/未集成则保留并记清恢复坐标。不得清理用户或其他任务资源。推送和部署单独遵守授权。
- 一个任务受阻时保留证据并继续无依赖任务；不得用 mock 成功、降低质量门槛或修改业务语义绕过阻碍。

## 等待、恢复与持续推进

- 等待使用宿主支持的非阻塞/有界工具，期间保持必要进度沟通。不要把自己 sleep 当成持久调度器，或声称已在后台自动继续。
- 无输出/超时不等于失败，不重派同文件写入者。检查代理状态和最后检查点，确认旧尝试不再写入后才重新分配；保留未完成变更。
- 未获最终交付时不要因一票完成就收口；继续授权范围的下一波。只在目标完成、真实权限/资料阻碍、用户暂停或明确交接时结束，并列出具体余项。
- 恢复时先读账本、实际代理状态、Git/worktree 和现有证据，再处理积压消息；从最早未完成步骤继续，已集成的不重做，仍运行的不另派。Codex 没有 Orca FIFO deliveryId/ack 合同，不伪造对应字段或终端唤醒。
- 最终核对全部写入者已返回或明确移交；汇报实际可用结果、验证、剩余风险、项目 MEMORY 是否更新。不把“代码已写”说成真实生产验收完成。
